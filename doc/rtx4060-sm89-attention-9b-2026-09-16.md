# softmax_attention 9B 几何适配交付小结（2026-09-16）

## 背景与结论

真机冒烟（Task F）前的最后一轮排查发现：此前记录的「kv_cache 9B 缺口」**结论有误**，真正的阻塞在
**softmax_attention 的 causal_cache 几何闭表**。本轮已全部修复并通过测试，9B text 主路径的 C++
代码缺口**全部打通**，仅剩权重下载（进行中）与转换、冒烟本身。

## 1. kv_cache「缺口」证伪 ✅（无需改）

| 判断 | 依据 |
|---|---|
| `kv_cache_append`（full 主路径）9B 本来就支持 | `kv_heads` 是运行时检查 `{4, 2}`（kv_cache_append.cpp:186），9B=4 命中 |
| `kKVHeads=8` 只烤死 prefix 路径 | 仅 `kv_cache_append_prefix`（speculator/MTP）使用；9B text-only 构建不含 MTP（Q8 被剔除），不经过 |
| 9B KV 几何与 full 路径精确匹配 | 官方 config：full-attn `head_dim=256`、`num_key_value_heads=4`；full 路径 `kFullHeadDim=256` |

## 2. 真正的缺口：causal_softmax_attention 闭表 ❌→✅

`require_causal_geometry` 只认 `(24,4)`/27B 与 `(16,2)`/35B；9B 是 `(16,4)`，**与 35B 撞 query_heads=16**
——所有按 `q_heads` 的二分支必须改用 kv_heads 区分。模型层（text.cpp）完全 config 驱动，无需改。

### 改动清单（9 个源文件 + 3 个测试文件）

| 文件 | 改动 |
|---|---|
| `geometry.cuh` | + `CausalD256H16Kv4 = CausalAttentionGeometry<16, 4, 1>`（SplitScale=1：KV/token 负载与 27B 的 kv4 相同） |
| `causal_softmax_attention.cpp` | 校验三分支；`split_capacity` 调用点 5 处传 kv_heads；`for_each_small_t_chunk` 加参 |
| `launch.h` | `causal_attention_split_capacity` 签名加 `kv_heads` |
| `small_t.cu` | split_capacity 三分支；两个 launch 入口三分支；**i8 launch 配置 GroupSize==4 专档**（见下） |
| `prompt.cu` | 2 处分发三分支 |
| `small_t_fp8.cu` / `prompt_fp8.cu` / `small_t_nvfp4.cu` / `small_t_k8v4.cu` / `prompt_k8v4.cu` / `prompt_nvfp4_non_rdc.cu` | 同款三分支（防 fp8 KV + (16,4) 静默错路由） |
| 测试 `causal_cache.cpp` | `kGeometries` 加 `d256-h16-kv4`（数据驱动，全用例自动覆盖）+ 能力门控（见 §3） |

### ★ 关键坑：i8 内核 warp 配置的整除性

`small_t_i8.cuh` 要求 `PVNtPerWarp = 256 / (ConsumerWarpsPerTile·8) ∈ {2,4,8,16}`。
GroupSize 4（9B）使 `RowCount=TT·4 → RowTiles=2`（27B 为 3），原 warp 数（24/12/6）全部失配：

| TokenTile≥6 原配置 | 9B 替代（CwPT→PVNt） |
|---|---|
| 24 warps | 16（CwPT=8→PVNt=4） |
| 12 warps | 8（CwPT=4→PVNt=8） |
| 6 warps（长窗） | 4（CwPT=2→PVNt=16） |

TokenTile==5 的两行 tile 分支同时接受 GroupSize 6 与 4。

## 3. 测试能力门控补齐（复现备忘录 §7 教训）

`ninfer_softmax_attention_test` 首次纳入 sm_89 覆盖，暴露两个既有问题：

1. **主路径无守卫调用 nvfp4/k8v4 子套件** → sm_89 请求被拒路由 → 未捕获异常 → abort
   （launchprobe 实测 `0xC0000409`，0.25s 无输出）。修复：nvfp4/k8v4 子套件与三处 5-storage 循环
   `#if NINFER_ENABLE_NVFP4` 包裹；`--nvfp4-only/--k8v4-only` 入口在非 Blackwell 构建返回 77（SKIP）。
2. **`plain_and_packed.cpp:47` 既有 C2131**：`constexpr double scale = 1.0/std::sqrt(72.0)`——
   MSVC 不支持 constexpr sqrt。改为字面量 `0.1178511301977579207`。

另在 `main.cpp` 加 stderr `[phase]` 阶段标记（stderr 无缓冲，fail-fast 不丢）。
